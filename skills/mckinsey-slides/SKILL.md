# McKinsey 風格簡報生成

麥肯錫風格之所以是麥肯錫風格，靠的不是配色，而是**論證結構**。配色只是外殼；真正難、真正容易被忽略的是「洞見型標題」與「金字塔原則」。生成簡報時，內容工作永遠比排版工作重要。

## 核心設計原則

1. **洞見型標題（Action Title）**——這是最重要、也最常被忘記的規則。每張投影片的標題必須是一句完整的結論陳述，而不是主題標籤。
   - ❌ 主題型：「營收概況」「市場分析」「執行方案」
   - ✅ 洞見型：「海外營收成長 24%，主因是東南亞通路擴張」「三大成長引擎中，定價策略貢獻度最高」
   - 如果來源內容只給了主題式大綱，你的工作是**先讀懂內容、算出/推論出結論，再把結論寫成標題**，不是把主題原封不動搬上去。

2. **金字塔原則 / MECE**——先講結論（governing thought），再展開支持論點；同一層級的論點之間要互斥且窮盡（Mutually Exclusive, Collectively Exhaustive），不要重疊、也不要漏掉明顯的一塊。整份簡報的順序是「結論先行 → 逐層展開支持證據 → 收尾」，不是「背景 → 過程 → 結果」的敘事式順序。

3. **視覺：白底、單色強調、扁平無裝飾**
   - 背景永遠是白色（`#ffffff`），主文字深藍（`#0B1F33` / `#1C2B39`），**只用一個強調色**（`#0F6FB5`）。
   - 不要漸層文字、不要霓虹光暈、不要玻璃感、不要每個卡片配一個不同顏色——那是科技新創 pitch deck 的語彙，會讓簡報看起來不專業。
   - 卡片/指標框用細邊框（1px）+ 一條強調色的細線（左邊或上邊 3-4px），不要用陰影或發光。

4. **Exhibit 編號**——每張內容投影片標題上方放一個小型大寫字母、字距拉開的標籤，格式 `EXHIBIT 01`、`EXHIBIT 02`……依序編號（封面與結尾頁不算）。標題下方放一條短的強調色細線（`.title-rule`）。

5. **圖表：單色 + 只凸顯一個重點**——這是麥肯錫圖表最容易被誤解的地方：不是「不能用顏色」，而是「一張圖只能有一個顏色重點」。找出這張圖真正要傳達的那個資料點（通常是最大值，但要看敘事重點而定——例如結論若是「最小的那項」，就凸顯最小值），把它塗成強調藍，其餘全部塗中性灰（`#B7C0C9`）。絕對不要每個類別配一個不同顏色的彩虹色盤。
   - 折線圖：整條線用強調藍即可，不需要灰階（趨勢圖本來就只有一條線）。
   - 只用來源中真實存在的數字，絕不可以自己捏造數據去填圖表。
   - 圖表或關鍵指標投影片下方，若能明確引用資料出處，加一行小字「資料來源：xxx」（`.source-note`）；沒有明確出處就整段不要加，不要編造來源。

6. **版型依內容形狀選擇，不是為了視覺變化而變化**：
   - `bullets` 一般要點（3-5 條）
   - `cards` 並列的概念/子主題（2-4 項）
   - `timeline` 時間序列或階段（依序）
   - `kpi` 少量關鍵指標，數字本身就是重點（2-4 項）
   - `compare` 前後對比/優缺點/A vs B（可用滑桿互動揭露）
   - `flow` 架構/流程/因果鏈（2-4 節點）
   - `chart` 有真實數列可比較（bar/line/pie）

## 生成流程

1. **讀懂內容，先想清楚每張投影片的「結論」是什麼**，再決定版型。如果使用者給的是原始資料/文件而非現成大綱，先在對話中列出你規劃的投影片標題（洞見型）給使用者過目，符合直覺的話再動手做完整 HTML——除非使用者已經明確說「直接做」不需要先確認。
2. 複製 `assets/template.html` 作為起點（不要重新從零寫 CSS，那份範本的配色/字級/間距已經是調過的成品）。裡面每個 `<!-- SLIDE: xxx -->` 對應一種版型，刪掉用不到的、複製需要重複的、依內容改寫文字。
3. 把封面 `.tag`／`h1`、結尾 `.tagline` 換成實際主標題與副標。
4. Exhibit 編號依實際留下的內容投影片張數依序重新編號（1, 2, 3……不要因為刪減版型留下跳號）。
5. chart 版型：`data-chart` 屬性裡的 JSON 換成真實 labels/values；下方 script 會自動找最大值上色，若敘事重點不是最大值，手動調整那段邏輯裡 `maxIdx` 的算法（例如改成找特定 index，或找最小值）。
6. 存成一個獨立 `.html` 檔案，直接用瀏覽器打開即可播放（Reveal.js 透過 CDN 載入，不需要建置流程）。用 `?print-pdf` 這個 query string 加在網址後面、透過瀏覽器列印成 PDF，可以匯出成一頁一張投影片的 PDF。

## 常見錯誤（自我檢查用）

- 標題讀起來像章節名稱而不是一句話結論 → 不合格，重寫。
- 圖表每個長條/扇形都不同顏色 → 不合格，改成「一個強調色 + 其餘灰階」。
- 背景用了漸層、光暈、或任何非白色的深色主題 → 那是 tech pitch deck 風格，不是這個 skill 的產出，改掉。
- 同一層級的重點彼此有明顯重疊（例如兩條 bullet 講的其實是同一件事） → 違反 MECE，合併或拆分。
